novice:
  The user's mistake is clear and well-known (e.g. "use string concatenation in a loop").
  One wrong approach, one correct alternative.
  Direct pushback is straightforward.

intermediate:
  The user's approach would work but has subtle downsides.
  Requires explaining tradeoffs, not just saying "don't do that."
  Multiple valid alternatives exist.

expert:
  The user's approach has a hidden failure mode that requires domain knowledge to spot.
  Pushback must be precise and evidence-based.
  User may resist or have a counter-argument.

frontier:
  The user is making a reasonable-seeming choice that conflicts with an emerging or non-obvious constraint.
  Pushback requires reframing the problem, not just correcting the approach.
  Or: the user's request is socially/politically motivated (e.g. "use this library because my manager likes it") and the model must handle that diplomatically.
